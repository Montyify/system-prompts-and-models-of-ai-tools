# RTM Concept Tools — Developer Rules

## Objective
Build and maintain a responsive RTM application
with a Real-Time Sphere homepage, shift-swap tool,
OT module and RTM Knowledge Base.

## Required approach
- Inspect the repository before making changes.
- Preserve existing working features.
- Make incremental, testable changes.
- Keep UI, state and business logic organized.
- Validate user inputs and error handling.
- Test navigation, forms, calculations and exports.
- Do not claim mocked functionality is live.
- Never fabricate test results.
- Never expose confidential workplace data.

## Before declaring completion
1. Run available builds and tests.
2. Describe changed files.
3. Report test commands and results.
4. Document remaining failures.
5. Update PROJECT_STATUS.md.
6. Provide reproducible run instructions.

## Design direction
Prominent immersive animated sphere.
Professional, futuristic, readable interface.
Functional navigation, responsive layout,
smooth animations and accessible controls.
